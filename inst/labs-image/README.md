# 图像里的线性代数（ROpenCV + ROpenEigen 实验教程）

上一套实验（`inst/labs/`）把教材的每一步算给你看，但结果都是**数字**：det = −3、
秩 = 2、稳态 = (4/13, 9/13)。数字是对的，可惜看不见。

这一套换一个做法：**把矩阵画成图**。同一个矩阵作用在一张图上，你能立刻看出它是
旋转、拉伸、翻转还是塌陷；同一个秩，你能看出「留几层」的差别；同一个特征向量，
你能看出它就是亮块摊开的那个方向。

八张图胜过八行公式，这是这套实验存在的全部理由。

## 需要什么

```r
ROpenEigen   # 线性代数（矩阵运算、分解、求解）
ROpenCV      # 读写图片、颜色转换、缩放、模糊、绘制
```

两个包缺一不可：ROpenCV 负责「把图变成矩阵」和「把矩阵变回图」，
ROpenEigen 负责中间那一步 —— 真正的线性代数。

```bash
Rscript run-all.R              # 顺序跑完 8 个实验（几秒钟）
Rscript run-all.R 01 03        # 只跑实验一、三
Rscript run-all.R --quiet      # 每个实验一行摘要
Rscript img04-systems.R        # 单个实验

# 包已安装但不想找路径时
Rscript "$(Rscript -e 'cat(system.file("labs-image","run-all.R",package="ROpenEigen"))')"
```

每张图都会存成 PNG，默认写到**当前目录的 `imgfigs/`**（可用环境变量 `LINALG_FIGS`
改路径）。跑完看这个文件夹就行；在 RStudio 里逐段执行则直接显示在 Plots 面板。

单个实验有三种跑法，**都不依赖工作目录**（和 `inst/labs/` 一样）：

| 入口 | 怎么用 | 靠什么定位 `imghelpers.R` |
|------|--------|--------------------------|
| 命令行 | `Rscript 路径/img04-systems.R` | `--file=` 里的脚本路径 |
| RStudio / `source()` | 打开脚本按 Source，或 `source("路径/img04.R")` | `source()` 写进 `ofile` 的脚本路径 |
| 包内回归测试 | `R` 跑 `tests/labs-image.R` | 已安装包的 `system.file("labs-image")` |

脚本开头的 `.lab_dir` 按「脚本自己所在目录 → 当前目录及其上层的包源码树 →
已安装的包」三级回退，所以从项目根目录、从任意别的目录、以及装好包之后都能跑。
**注意**：定位的是 `imghelpers.R`，图仍然写到**当前目录**的 `imgfigs/` ——
从哪儿跑就在哪儿出图。

## 八个实验

### 实验零 · 图像就是矩阵

把图拆开：`240 × 320 × 3` 的数组、0..255 的取值、三个通道各是一张灰度图。
灰度化写成 `0.299R + 0.587G + 0.114B`，与 `cv_cvtColor()` 的最大差 **0.445**
（只差四舍五入）。再逐像素做加法、乘法、反色、gamma，看清「矩阵运算」和
「图像处理」是同一件事。

顺带讲清 OpenCV 的 `depth`：`Mat()` 一个 double 矩阵得到 CV_64F，
`cvtColor` 会直接拒收；要 CV_8U 得先转 `raw`。所有实验的规矩由此定下：
**算的时候用 R 的 double，交给 OpenCV 之前走 `il_cv()`。**

### 实验一 · 行列式：面积、翻转、塌陷

- 单位正方形经 `A = [[2,0.5],[0,1]]` 变成平行四边形，鞋带公式给面积 **2**，
  与 `|det A| = 2` 一致；再把一张 80×80 的白方块变过去，数亮像素得 **12800**，
  比值正好 **2.0000**。
- `det < 0`：图像镜像看到字母 A 倒过来；两次镜像（det 相乘 = +1）与旋转 180°
  的像素差为 **0**。
- `det = 0`：`S = [[1,1],[1,1]]` 把所有点压到直线 y = x 上，正映射后的图只剩
  **0.16%** 的像素非黑。顺便看到 `solve()` 返回 `Inf/-Inf` 而不是报错。
- 3×3：RGB 就是三维向量。交换 R/B（det = −1）图像红蓝互换；绕灰度轴转 120°
  （det = 1）体积守恒、灰色仍是灰色；秩 1 的 `[[1/3]×3×3]` 一步把彩图变灰度。

### 实验二 · 矩阵运算与初等变换

- **乘法是复合**：`R30 %*% S2` 与 `S2 %*% R30` 两张图 RMSE = **84.23**，
  可交换的话应当是 0。
- **逆矩阵**：`A^{-1}A − I` 只有 **1.1e-16**；但图上往返一次整图 RMSE 有 30.5，
  拆开看：31.7% 是补的黑框、真正变的像素只占 **3.46%**、全在硬边缘。
  代数上的可逆 ≠ 离散图像上的可逆。
- **初等矩阵**：行交换矩阵左乘 = 图像上下翻转（与 `gray[h:1, ]` 差 0）；
  行倍加 `E[i, i−12] = 0.6` = 上移 12 像素的重影；行倍乘只让一行变亮。
  全程只用了矩阵乘法，没有任何图像函数。
- **秩**：`outer(v, u)` 造的图秩为 1，是横条纹；`k` 层 SVD 近似的 RMSE
  从 40.19（k=1）降到 5.02（k=60）。
- 手写最近邻 vs `cv_warpAffine` 双线性：RMSE **11.438**，差异只占 1.78% 的像素，
  但全在斜边上。

### 实验三 · 图像是向量

- 平移 30 像素的两张图夹角 **18.68°**，模糊前后只差 **6.94°** —— 余弦越大越像。
- 「反相图」`255 − A` 与 A 的余弦是 **0.757**，看着相反却不正交；减掉均值后变成
  **−1**。共同的大均值把余弦抬高了 —— 这就是「去均值 = 投影到与常向量正交的
  子空间」。
- **Gram-Schmidt**：B 里 A 方向的坐标 1.026943，残差与 A 的内积 −1.95e-07，
  `||R||/||B|| = 32.0%`。
- **投影**：把模糊图投影到 `span{A, B}`，长度保留 **99.4%**（能量 98.81%），
  残差只剩 10.91% 的长度，且与 q1、q2 的内积是 8.9e-12 / 2.3e-11。
- 三张图摞成 3 × 76800 的矩阵，秩 = 3，但奇异值 75662 / 11286 / 3517 ——
  「线性无关」和「几乎相关」是两件事。

### 实验四 · 线性方程组：把模糊的图还原

- 一行像素的模糊写成 `b = T x`，T 是 320×320 的 Toeplitz 矩阵。`kappa(T)` =
  **1.62e6**。
- 无噪声时解出来与原行 RMSE = **0**；加 σ = 1 的噪声后 RMSE 飙到 **31710**
  （像素上限才 255）。1 个灰阶的噪声被放大四个数量级。
- 正则化 `(T'T + λI)x = T'b`：λ 从 0.0001 扫到 100，RMSE 是 U 形 ——
  32.8 → **14.9**（λ = 0.001）→ 76.8 → 146.7。这条 U 形曲线就是「偏差-方差权衡」。
- 整幅图 240 个方程组共用**一次 LU 分解**：直接解 RMSE **15132**，
  正则化解 **8.39**（λ = 0.003）。
- 顺带验证：矩阵乘出来的模糊与 `cv_GaussianBlur(15×15, σ=3)` 的 RMSE 只有 **10.4**。
- 最小二乘拟合那条黑线：135 个方程、2 个未知数，残差平方和 11.5、最大偏差 0.62
  像素；正规方程与 SVD 差 5.6e-17。

### 实验五 · 特征值与特征向量

- 把亮度当权重算 2×2 协方差：特征值 4888.5 / 8843.1，主轴 **−7.18°**，
  两个特征向量内积 0（实对称必正交）。把点云整体转 30°，特征值一个不变、
  主轴正好变成 22.82° —— 这就是 `R C R'` 的相似变换。
- `Q'Q − I` 误差 2.2e-16、`QΛQ' − T` 误差 4.4e-16；图上的三步复合与直接变换
  只差重采样（RMSE 来自三次最近邻，与 1e-16 无关）。
- 幂迭代：从 (1,0) 出发，与主方向的夹角 11.16° → 3.60° → 1.15° → 0.37° →
  0.12° → 0.04°，每轮乘 **0.3192**，正好等于 λ₂/λ₁。
- `A^k` 打在图上：k = 8 / 24 / 60，两个方向的长度比 1.62 / 4.22 / 36.64，
  图像最终塌成条纹 —— 和实验一的 det = 0 是同一件事的极限。

### 实验六 · 二次型

- 三个 2×2 矩阵的 `x'Ax = 1`：正定是椭圆、不定是双曲线、半定是两条平行线
  （用极坐标 `r = 1/sqrt(q(cosθ, sinθ))` 一步画出来）。
- 椭圆半轴 = `1/sqrt(λ)` = 1.2295 与 0.7584，面积 `π/sqrt(det)` = 2.9296。
- 用 `exp(−x'Ax)` 造斑点：A1 细长、A2 换向、A3 是圆、不定型给马鞍。
  **方向是反的**：特征值大的方向斑点反而窄。
- 四种判别法（顺序主子式 / 特征值 / Cholesky / 惯性指数）逐个跑一遍，结论一致；
  参数 a 从 1.6 降到 0.8，`[[a,1],[1,a]]` 从正定经半正定（a = 1）走到不定。

### 实验七 · SVD：一张图能压到多小

- 240 个奇异值里，前 1 个就占 **93.34%** 的能量，前 10 个占 **99.04%** ——
  图的「大结构」比细节重要得多，这正是压缩能成立的前提。
- 意外收获：后 **53 个奇异值精确为 0**，`rank(A) = 187` 而不是 240。测试图有大片
  纯色，行向量大量线性相关；所以「最大 / 最小」只会算出 `Inf`，有效的条件数是
  非零奇异值之比 42195。
- 秩 k 近似的完整数据表：k = 1 时 PSNR 16.06 dB（压缩比 136.9:1），
  k = 20 时 26.96 dB（6.84:1），k = 50 时 32.68 dB（2.74:1）；
  k 加到 187 已经是 5.5e-13，再加到 240 一个像素都没好 —— 零奇异值加了也白加。
- Eckart-Young：k = 20 的实测 RMSE 11.53567 与 `sqrt(Σ_{i>k} σ_i²/(mn))`
  **完全相等**（相对误差 < 1e-12，代码里就是这么断言的）。
- 彩色图三个通道各拆一次，k = 30 时 PSNR 28.88 dB、压缩比 4.56:1。
- 对照组：直接缩到一半再放大回来，PSNR 27.81 dB —— 与 k = 20 的 SVD 各有胜负，
  一个整体糊、一个保结构丢细节。

## 三个必须先接受的约定

1. **颜色是 0..255 的 double，顺序是 RGB。** `cv_imread()` 给的是 BGR，
   读进来立刻翻一次，之后一律按 RGB 处理。写回文件时再交给 `il_cv()`。
2. **图像是 `(高, 宽, 通道)` 的三维数组**，与 OpenCV 的 `(rows, cols, ch)` 一致，
   与 R 的「列优先」也不冲突 —— 但 `as.vector()` 的顺序是列优先，写映射函数时
   必须小心（`il_warp_*` 里专门注释了这一点）。
3. **y 轴朝下。** 图像的行号往下增，数学上的 y 往上增，两者差一个符号。
   `il_warp_inv()` 内部先中心化再取负，教材上的矩阵可以直接用。

## 两个包各自扮演什么

| 环节 | 用谁 | 为什么 |
|------|------|--------|
| 读图、写图、缩图 | `cv_imread` / `cv_imwrite` / `cv_resize` | 图片格式这种东西不值得自己写 |
| 颜色 | `cv_cvtColor`（对照手算的加权和） | 手算一遍才知道灰度是什么 |
| 几何变换 | `il_warp_fwd` / `il_warp_inv`（手写） + `cv_warpAffine` | 手写才知道「矩阵怎么作用在坐标上」 |
| 矩阵运算、分解、求解 | ROpenEigen | 这才是教材的内容 |
| 显示 | `plot(cvMat)` / `as.raster()` | 一行出图 |

手写 `il_warp_*` 还有一个副作用：它把「正映射」和「反映射」的区别摊开了。
`det = 0` 时正映射还能画（压成一条线），反映射根本不存在（要求逆）——
这正是教材说「不可逆就没有逆映射」的图示。

## 图片从哪来

没有外部素材，也不依赖任何数据文件。默认的测试图是 `il_chart()` **现场画出来的**：
开一个 PNG 设备、画几个几何体和一个字母 A、关掉、再用 `cv_imread()` 读回来。
这条链路本身就是一次「图形 → 文件 → 解码 → 矩阵」的演示，而且好处是
**每次跑出来一模一样**，所有数字都可复现。

想换成自己的照片：

```bash
LINALG_IMG=D:/photos/cat.jpg Rscript img02-operations.R
```

## 常见坑（都在这套实验里踩过）

- **CV_64F 喂给 cvtColor 会报 `Unsupported depth`。** `Mat(double 矩阵)` 得到的是
  64 位浮点，OpenCV 的绝大多数函数只吃 8U/16U/32F。用 `il_cv()`。
- **`cv_GaussianBlur(src, ksize, sigmaX)` 的 ksize 是一个长度 2 的向量**，
  写成 `cv_GaussianBlur(src, NULL, c(9,9), 3)` 会把参数错位，报
  `Expecting a single value: [extent=2]`。
- **`eigen_svd()` 的成员是方法不是字段**：写 `S$singular_values()`、`S$u()`，
  漏了括号拿到的是函数本身。
- **`eigen_eigen()` 只读下三角**，非对称矩阵会给出看似合理但错误的结果；
  一般矩阵用 `eigen_geigen()`。还要读特征值/特征向量就直接用
  `eigen_values()` / `eigen_vectors()`，别去 `$` 挖 solver 的成员
  （会拿到 closure，报 `object of type 'externalptr' is not subscriptable`）。
- **`solve(eigenMat(奇异矩阵))` 返回 NaN/Inf 而不报错**，用之前先看 `rcond`。
- **base R 没有 `cond()`**，条件数用 `kappa()`；ROpenEigen 侧有 `eigen_rcond()`
  （给的是倒数，别和 `kappa()` 混着看）。
- **纯色区域取不出数据点**：`which.min()` 在一整列相同值里会返回第一行，
  实验四的直线拟合就因此先踩了一脚。
- **图上的标题一律用 ASCII**：Windows 的默认图形设备画中文会掉字。
